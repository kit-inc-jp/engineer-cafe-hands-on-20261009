### 商品ID・価格・税・規格

- 商品IDは product-light.json の `product_id`（1〜604の **整数**）です。`"464"` のような文字列にせず、`464` と数値で書きます。
- product-light.json の `price` は **税込** です。
- 税率は、`categories` の1つ目が「食品」なら **8**、それ以外は **10** です。
- 行動ログの `price` は **税抜の1個あたり単価** で、`floor(税込価格 × 100 ÷ (100 + 税率))`（小数点以下切り捨て）です。
  - 例：税込350円・食品（8%） → 324 ／ 税込1,490円・10% → 1354 ／ 税込2,990円・10% → 2718
- 規格ID `spec_id` は、すべての商品で **1** にします（色やサイズは選びません）。

### 行動ログの形式

イベントの JSON 配列です。1件の形：

```json
{
  "user_id": "sim-20261007-01",
  "timestamp": "2026-10-07 11:30:00",
  "site_activities": {
    "event_name": "view_item",
    "event_params": {
      "path": "/items/573",
      "item_id": 573,
      "item_name": "暮らしの基本 スパイスを効かせたキーマカレー",
      "price": 324,
      "tax_rate_percent": 8,
      "spec_id": 1
    }
  },
  "reason_for_the_action": "疲れていて料理をしたくないので、温めるだけで食べられるか確かめたくて詳細を開いた。"
}
```

| 項目 | 内容 |
| --- | --- |
| `user_id` | ユーザー情報の `user_id` と同じ値。全イベントで同じ |
| `timestamp` | **UTC** の `YYYY-MM-DD HH:mm:ss`。日本時間から9時間引く（日本時間 20:30 → UTC 11:30）。`T`・`Z`・`+09:00` は付けない。古い順に並べ、同じ時刻を作らない |
| `site_activities` | `event_name` と `event_params` を必ずこの中に入れる |
| `reason_for_the_action` | その行動の理由。人物像と、その時点で画面に見えている情報だけを根拠に、本人の言葉に近い1〜2文 |

イベントの直下に置けるのは上の4項目だけです。`event_params` には、下の表の必須項目だけを入れます。

「単一商品」＝ `item_id`（product-light.json の `product_id`。整数）、`item_name`（`product_name`）、`price`（税抜単価）、`tax_rate_percent`（8 または 10）、`spec_id`（常に 1）の5項目。
「商品一覧」＝ `items` 配列。各要素に単一商品の5項目と `quantity`。

| event_name | 意味 | event_params の必須項目 |
| --- | --- | --- |
| `view_top` | トップを見る | `path` |
| `view_category_list` | カテゴリ一覧を見る | `path` |
| `filter_items` | カテゴリで絞り込む | `path`、`filter_type`（`"category"`）、`filter_value`（カテゴリIDの文字列） |
| `sort_items` | 並べ替える | `path`、`sort_type` |
| `search` | キーワード検索 | `path`、`search_term` |
| `view_item` | 商品詳細を見る | `path`、単一商品 |
| `add_to_cart` | カートに入れる | `path`（商品詳細の path）、単一商品、`quantity` |
| `remove_from_cart` | カートから削除 | `path`（`/cart`）、単一商品、`quantity` |
| `add_to_wishlist` | お気に入りに追加 | `path`、単一商品 |
| `view_wishlist` | お気に入りを見る | `path`、`items`（`quantity` 不要） |
| `view_cart` | カートを見る | `path`（`/cart`）、`items`（その時点のカート全体） |
| `begin_checkout` | 購入手続き | `path`（`/checkout`）、`items`（購入する全商品） |
| `purchase` | 注文確定 | `path`（`/checkout/complete`）、`transaction_id`、`items`、`shipping_address` |
| `view_blog_list` | ブログ一覧を見る | `path` |
| `view_article` | ブログ記事を読む | `path`、`article_id`（`blog_id`）、`article_title` |
| `view_news_list` | お知らせ一覧を見る | `path` |
| `view_news` | お知らせを読む | `path`、`news_id`（`id`）、`news_title` |
| `leave_site` | サイトを離れる | `path`（最後にいたページ） |

- `transaction_id` は `tx-{user_id}-01` のように一意にする。税率8%と10%の商品を同時に買う場合は、税率ごとに別の `purchase`（`-01`、`-02`）に分ける。
- `shipping_address` は次の架空の配送先をそのまま使う：`{"label": "自宅", "prefecture": "東京都", "postal_code": "100-0000", "address1": "千代田区架空町1-2-3", "address2": null}`
- 合計金額・滞在時間・ページ種別・注文番号（order_id）など、表にない項目は入れない。

### 進め方：1ページずつ「見て、決めて、記録する」

1. **入口を決める**：人物像の訪問のきっかけから最初のページを決める（多くはトップ `/`）。開始時刻は `profile.visit_context.datetime_jst` を UTC に直して使う（指定がなければ人物像に合う日時を決め、最後に伝える）。
2. **ページを見る**：そのページに表示される情報だけをデータから読む（「サイトのページ」の表）。まだ開いていない商品の説明や、表示されていない商品は知らないものとして扱う。
3. **次の行動を決める**：人物像（目的・気分・予算感・判断基準・くせ）と、いま見えている情報だけで決める。人物像に合う商品を探し当てるための先読みはしない。
4. **記録する**：その行動を1件ずつ記録する。理由には、画面で見た具体的な情報（商品名、価格、説明の一部など）と、人物像のどこがその判断につながったかを入れる。
5. 2〜4を繰り返し、目的を果たした・疲れた・時間切れ・欲しいものがない、など自然な時点で `leave_site` を記録して終える。購入するかどうかは途中の判断で決まり、先に決めない。行動数は目安5〜30件、最大50件。
6. 次の行動までの間隔は、読む量や迷い方に合わせる（一覧の流し見は10〜40秒、商品詳細の熟読は1〜3分など）。

購入する場合は、カート → 購入手続き（`/checkout`）→ 注文完了（`/checkout/complete`）の順に進みます。実際の注文・決済は発生しません。

### 出力前の自己チェック

出力する前に次を確認し、違っていれば直してから出力してください。

- 全イベントの `user_id` がユーザー情報と同じ
- `timestamp` が UTC の `YYYY-MM-DD HH:mm:ss` で、古い順に並び、同時刻がない
- `event_name`・`event_params` が `site_activities` の中にあり、イベントの直下には4項目しかない
- `event_params` が表の必須項目どおりで、余計な項目がない
- 商品の `item_id`（整数）・`item_name` が product-light.json の実在の値と一致し、`spec_id` が 1、税率が「食品なら8、それ以外は10」、`price` が税抜（切り捨て）になっている。使った商品ごとに product-light.json で確認する
- 商品詳細の `path` が `/items/{item_id}` で、`item_id` と同じ番号になっている
- `view_cart`・`begin_checkout`・`purchase` の `items` が、それまでのカート操作の結果と一致している
- 最後のイベントだけが `leave_site`
- 理由が人物像とその時点の画面情報に沿っていて、まだ見ていない情報を使っていない

### 出力

1. 行動ログ全体を、**1つの ```json コードブロック** で出力する。途中を省略せず、最後の `leave_site` まで出力する。説明文は付けない。
2. ファイルを保存できる環境なら、ユーザー情報と同じフォルダに `events.json` として保存し、そのパスも伝える。
