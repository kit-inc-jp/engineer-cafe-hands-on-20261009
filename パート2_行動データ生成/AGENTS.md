# 仮想ユーザーの行動ログ ハンズオン

架空のECサイトを訪れる仮想ユーザーをAIと一緒に作り、その人の1回分の訪問（1セッション）の行動ログを作って、ブラウザで流れを見るハンズオンです。参加者は Python などをインストールせず、AIのチャット（Web版のGemini・ChatGPT、またはClaude Code・Codexなどのエージェント）とブラウザだけで進めます。

このファイルは、このフォルダで作業するAIエージェント向けの説明です。参加者への案内も、ここに書いた手順に沿って行ってください。

## エージェントとしての進め方

参加者から①〜③を頼まれたときは、次のとおりに進めます。

| 依頼 | すること |
| --- | --- |
| ① ユーザーを作って | `prompts/01-create-user/prompt.txt` を読み、その本文を自分への指示として実行する（参加者への逆質問から始める）。確定したJSONを `outputs/{YYYYMMDD}-{人物を表す英小文字の短い名前}/user.json` に保存する |
| ② 行動ログを作って | `prompts/02-create-session/prompt.txt` を読み、その本文を自分への指示として実行する。添付の代わりに、同じフォルダの `product-light.json`・`blog-light.json`・`news-light.json` を読む。ユーザー情報は①の `user.json` を使う。結果を同じ実行フォルダの `events.json` に保存する |
| ③ 表示して | AIの作業は不要。参加者に、`viewer/session-viewer.html` をブラウザで開き、`user.json` と `events.json` を画面上部の欄に置くよう案内する |

### 守ること

- **プロンプトを書き換えない：** 手順の正は、プロンプト本文（`prompt.txt`）とこのファイルです。実行時に勝手に変えず、変える必要があれば参加者に提案します。
- **データは読み取りだけ：** `prompts/02-create-session/` のJSONと `viewer/ec-data.js` は変更しません（元データとの関係は「フォルダ構成」を参照）。
- **商品は実在するものだけ：** 商品・記事・お知らせは、データに実在するものだけを使います。商品IDは `product-light.json` の番号（1〜604の整数）で、推測で作りません。
- **参加者にプログラムを実行させない：** 参加者にコマンド実行やソフトのインストールを求めません。
- **実在の個人情報を使わない：** 実在の個人情報・住所・決済情報は使いません。購入時の配送先は、②のプロンプトにある架空の配送先を使います。

## 参加者の手順

| 手順 | 使うフォルダ | AIに渡すもの | できるもの |
| --- | --- | --- | --- |
| ① 仮想ユーザーを作る | `prompts/01-create-user/` | `prompt.txt` の本文 | ユーザー情報のJSON（`user.json`） |
| ② 1セッションの行動ログを作る | `prompts/02-create-session/` | `prompt.txt` の本文＋同じフォルダの `product-light.json`・`blog-light.json`・`news-light.json`（添付） | 行動ログのJSON（`events.json`） |
| ③ 表示する | `viewer/` | なし（AI不要） | 行動の流れの表示 |

### ① 仮想ユーザーを作る

1. AIのチャットを開きます。
2. `prompts/01-create-user/prompt.txt` を開き、全文をコピーして貼り付けます。
3. AIが質問するので、選択肢の番号か自由な言葉で答えます。JSONを自分で書く必要はありません。
4. 最後に出力されたJSONを `user.json` として保存します（ダウンロードした名前のままでも③で使えます）。

### ② 1セッションの行動ログを作る

1. ①と同じチャットで続けるか、新しいチャットを開きます。
2. `prompts/02-create-session/` の `product-light.json`・`blog-light.json`・`news-light.json` の3ファイルを添付します。
3. `prompts/02-create-session/prompt.txt` の全文をコピーして貼り付けます。①と別のチャットの場合は、本文の「ユーザー情報」欄にある `（ここに user.json の中身を貼り付ける）` を、①で作ったJSONに置き換えます。
4. 出力された行動ログのJSONを `events.json` として保存します。

会社情報とカテゴリ一覧はプロンプト本文に含めているため、添付は不要です。

### ③ 表示する

1. `viewer/session-viewer.html` をダブルクリックしてブラウザで開きます。
2. 画面上部の「ユーザー情報」「行動ログ」の欄に、それぞれ①②のファイルを置きます（「ファイルを選択」か、欄の上へドラッグ＆ドロップ）。置いた欄のデータとして読み込むので、ファイル名は問いません。AIのチャット画面でJSONの文字列を選択し、欄へドラッグしても入ります。
3. 行動ログを入れた時点で、行動の流れが自動で表示されます（ユーザー情報は後から入れても反映されます）。

## 完成例

`outputs/20261007-blog-weekend-cook/` に、①〜③で作るファイルの例があります（ブログ経由で台所道具と食品を買うユーザー。インタビュー回答は想定で記入したサンプルです）。`session-viewer.html` をブラウザで開くと表示を確認できます。

## フォルダ構成

```text
AGENTS.md                このファイル（CLAUDE.md からも読み込まれる）
prompts/
  01-create-user/
    prompt.txt           ①のプロンプト本文
  02-create-session/
    prompt.txt           ②のプロンプト本文
    product-light.json   ②で添付する商品データ
    blog-light.json      ②で添付するブログ（画像なし・本文は文章だけ）
    news-light.json      ②で添付するお知らせ（画像なし・本文は文章だけ）
viewer/
  session-viewer.html    表示用ビューア（左：行動の目次、右：理由と見ていた画面）
  ec-data.js             ページ再現用データ（ビューアと同じフォルダに置く）
outputs/                 実行ごとの成果物
```

`prompts/02-create-session/` の3ファイル、②のプロンプト本文に含めた会社情報・カテゴリ一覧、`viewer/ec-data.js` は、どれもECサイトの元データ（product・blog・news・company・product_category）から作った写しです。元データはこのフォルダには含めず、別の場所で保管しています。データは更新しない前提です。

### 商品IDについて

- 商品IDは1〜604の番号で、全ファイル共通です。`product.json`・`product-light.json` の `product_id`、`blog.json`・`news.json`（と light 版）の `product_id`（紹介商品・関連商品）、行動ログの `item_id` が同じ番号を指します。
- 行動ログの注文番号（`transaction_id`）は `tx-{user_id}-01` の形です。
- 長いID（UUID）はデータに残していません。1文字違うだけで参照が壊れ、人もAIも正しく書き写しにくいためです。画像URL内の長い文字列は画像の置き場所（S3のパス）なので、そのままにしています。
- `product-light.json` は `product.json` と同じ商品・同じ順番で、②の添付用に項目を減らしたものです。`blog-light.json`・`news-light.json` も②の添付用で、画像URLを除き、本文をHTMLから文章だけ（「■」が見出し、「・」が箇条書き）にしたものです。
- 税率は「食品」カテゴリの商品が8%、それ以外が10%です。規格ID（`spec_id`）は常に1です（規格1の価格は全商品で商品価格と同じです）。

## ビューアでできること

画面の左に行動の目次（行動名・時刻・対象）、右に選んだ行動の理由と、そのとき見ていた画面を表示します。

主な機能：

- ユーザー情報（人物像、訪問の状況、判断基準など）の表示
- そのとき見ていたページの再現（トップ、カテゴリ一覧、検索・絞り込み結果、商品詳細、ブログ一覧・記事、お知らせ一覧・本文、カート・注文）と、その時点のカート・お気に入り・購入
- ログの確認：ユーザーIDの一致、時刻の順序、イベント別の必須項目と不要な項目、カートの中身と `view_cart`・`purchase` の一致、注文内の税率混在、最後が `leave_site` か、商品ID・商品名・税率・税抜単価、記事・お知らせのタイトルがデータと一致するか

ページの再現には、ビューアと同じフォルダの `viewer/ec-data.js` を使います。ダブルクリックで開いた場合も自動で読み込まれます（ブラウザの制限で、`file://` で開いたページは相対パスのJSONを読めないため、JSとして同梱しています）。画像はデータ内のURLをそのまま表示し、読み込めない場合は代わりの枠を表示します。

## 行動ログを読み込めない時

AIが決まりと違う形式で出力すると、ビューアの上部に「読み込めませんでした（直す点 ○種類）」が表示されます。

1. 一覧で、どの行動（「3〜4, 6件目」「全14件」など）の、何を、どう直すかを確認します。同じ問題は1行にまとめて表示されます。
2. 「AIへの修正依頼文をコピー」を押し、行動ログを作ったAIのチャットに貼り付けます。依頼文には、問題の一覧、正しい形式、直す対象のJSONが含まれます。
3. AIが出力し直したJSONを、画面上部で読み込み直します。問題が残っていれば、もう一度一覧が出ます。

- 「表示できない」は形式の誤り（`site_activities` がない、イベント名が違う、時刻の形式が違う、JSONの書き方の誤りなど）で、直すまで表示されません。
- 「要修正」は表示はできるが直すべき点（必須項目の不足、不要な項目、商品IDや価格の不一致など）です。
- 商品名から実在の商品ID（product-light.json の番号）・税率・税抜価格を探して「直し方」に書き出します。
- JSONの書き方の誤り（余分なカンマ、カンマ抜け、`'` の使用、途中で切れた出力、前後の説明文）は、行・文字位置と原因を表示します。AIの出力によく付く ```json の囲みは自動で外します。

エージェントが修正依頼文を受け取った場合は、その一覧をすべて直し、`events.json` を上書き保存します。

## Web版のAIを使うときの注意

- ②では3ファイルの添付を忘れないでください。添付がないと、AIが実在しない商品IDを作ることがあります（プロンプトでは、読めない場合は止まるよう指示しています）。
- 出力が長いと途中で切れることがあります。最後が `leave_site` で終わっているか確認し、切れていたら「続きを出力して」ではなく「省略せず最初から全体を出力して」と依頼してください。
- 出力された行動ログは必ずビューアで読み込み、問題が出たら上の手順で直してもらいます。
